# Claude 总控 · 完整手册

> 快速上手请看客户端顶栏 **?** 按钮的「30 秒看懂总控」图文速览;本文是查细节用的完整手册。

一个把 Claude Code 的「项目 / 会话 / 记忆 / 终端 / 通知」装进同一个桌面客户端的驾驶舱。

## 一、界面速览(三栏)

### 顶栏 · 状态条

从左到右:

- **完成横幅**:最新干完活的会话,点一下直接定位过去
- **额度 N%**:官方口径,来自 `claude /usage`。点开看当前会话 / 本周 / 本周 Fable 的分项
- **🔥 5h · 今日**:本机记账的**累计消耗**,把每一轮加起来。点开看排行和明细
- **上下文 X / Y**:当前会话的**瞬时占用**,以及它大概压在哪(Y 的来历见下面,**不是**一个确定的数)
- **小九 API**:本机控制 API 的状态(就绪 / 排队 / 执行中 / 异常)
- **金色「有新版」**:Claude Code 有更新,点一下就在终端里跑 `claude update`

**「🔥 累计」和「上下文 瞬时」是两个完全不同的口径,别看混:**

- 🔥 是**花掉的总量**,只会往上涨,反映的是你烧了多少钱
- 上下文是**这一轮驮了多少**,会被压缩打回去再爬上来,反映的是你离自动压缩还有多远

**上下文这个条怎么用:**

**这里有两条线,是两件事,别混:**

- **橙色 = 你自己的「收尾提醒线」**,默认 **20 万**,在 ⚙️ 里可改(关 / 15 万 / 20 万 / 30 万 / 50 万 / 80 万)。
  它和官方压缩毫无关系,纯粹是**提醒你该主动开新会话了**。
  变橙时的正确动作:让它**先把结论写回项目文件**(`修改记录.md` / 记忆),然后 `/clear` 开新会话
- **红色 = 官方自动压缩快到了**,这是被动兜底,不是你该等的东西。
  压缩不是「清掉」而是**把前面的对话重写成摘要**,细节会掉;而且压一次要把当时整个上下文完整读一遍,很贵。
  所以红色的意思是「已经拖太久了」,不是「正常流程走到这里」

**那个分母 Y 是怎么来的 —— 分两种情况,差别很大:**

- **这个会话已经自动压过一次** → 分母直接用**实测值**:上次压缩前最后一轮的真实读数。
  这是唯一不用猜的数,红线画在它往前 5% 处。悬停会写明「这个会话实测压过一次:N tok」
- **还没压过** → 只能**估**:`autoCompactWindow` 减 13000(官方留 13000 给压缩自己用),
  配 100 万 → 估算上限 **98.7 万**,红线取其 **90%**(**88.8 万**);
  窗口配得很小(低于 21.3 万)时改取「再减 2 万」那个,因为它更早

**⚠️ 没压过的时候那个估算值真的会错,而且错得不小(实测,不是理论):**

官方真实窗口 = `min(模型自己的窗口, 你配的值)`,而**模型窗口是服务端下发的,客户端读不到**
(查过 `claude.exe`,不是硬编码表;本机那份缓存是空的)。再叠上四层配置和服务端下发值。

2026-11-10 把 205 份转录全扫了一遍,77 次自动压缩。单看那天的 18 次:
真实压缩点从 **21.3 万一直散到 60.8 万**,中位 **26.8 万**。
这 18 次里**只有 5 次药丸是红的**;收尾线如果还是老的 30 万,**有 7 次压缩发生时药丸全绿**(改成 20 万之后这 18 次全部有提示)。

**最硬的一条证据**:那天把窗口改回 100 万之后,已经在跑的会话
13:56 / 14:24 / 14:42 / 16:00 四次压缩**仍然发生在 26.3~26.5 万** ——
也就是说正在跑的会话压根不认新配置,真实上限只有估算值(98.7 万)的四分之一出头。
所以改完 `/autocompact` 别指望当前会话跟着变,得重开会话才算。

**所以这里要把话说准:压过一次之后红线也只是「不那么瞎」,并不等于准了。**
实测真实上限在同一个会话里是**往下漂**的:59 对「同一会话连续两次自动压缩」里,
**34 对后一次压得更早**(例:99.8万 → 69.8万 → 41.3万 → 25.6万 是同一个会话的四次)。
拿上一次的点当分母,下一次就偏高 —— 偏高的后果是**该红的时候还是绿的(假绿)**。

按三月自己这 77 次压缩推演过(窗口按现在的 100 万算):
- **纯估算红线**(888300,会话没压过时就是这条):全部 **41/77**;**11-09 之后那 28 次一次都没拦住(0/28)**
- **出厂逻辑**(有实测点就改用实测点校准):全部 **51/77**;11-09 之后 **5/28**
- **收尾线放 20 万**(口径:红或橙,只要有一个就算提醒到了)
  11-09 之后那 28 次**全部有提示**(5 红 + 23 橙);全部 77 次里命中 **76 次**,只漏 1 次
  (漏的那次是 2026-05-23 的 16.4 万,那个会话之前没压过、红线只能用 88.8 万的估算值;放 15 万能 77/77,但日常会吵;放 30 万 11-09 之后漏 8 次)
  ⚠️ 这个「0 漏」的样本只有 **2 天、10 个会话、28 次压缩**,而且最低那次(21.3 万)只比线高 **6.6%** —— 别当成有余量。
这就是默认值定在 **20 万** 的来历 —— 真正该依赖的是**你自己那条橙色收尾线**:
它是个绝对 token 数,不受服务端下发、不受配置漂移、也不受实测点往下漂的影响。

- 实测有压在**超过分母**之后的:77 次里有 **39 次**读数超过 98.7 万,最高 **999950(估算上限的 101.31%)**,
  所以**超过 100% 照样是红**,不会在最危险的那一刻变灰
- 显示成「**X / 阈值待定**」(虚线框)= 占用**大幅**超出(>115%)分母,说明这个分母不可信,
  **只报数、不拿它报警**;但**你那条收尾线照样有效** —— 过了线还是会变橙
- **只对正在跑的会话显示**(最后一轮在 30 分钟内)。新开的终端标签在拿到真会话 ID 之前**不显示**,
  不会顶着上一个会话的读数糊弄你
- 真正该开新会话的判据是**任务换了没有,不是 token 到没到**。一个大任务驮到二三十万是正常的(到收尾线只是提醒你找个收口的地方,不是必须立刻停)
- **已知限制(方向很重要)**:实测点只存**最后一次**,而真实上限在会话里往下漂,
  所以**更常见的是假绿**(分母比真上限大 → 百分比偏小 → 该红没红),11-09 之后 28 次里红线只命中 5 次。
  反方向(某次压得特别早 → 报一段假红)也有:读数超过那个点 1.15 倍之后自动作废翻绿,
  看起来就是「涨了一点点却从红变绿」。**两个方向都别指望红线,看橙线**。
  参考散布:11-09 之后 28 次真实压缩点散在 **21.3 万 ~ 82.9 万**(最高是最低的 3.9 倍)
- 重启客户端后会在后台悄悄跑一次**回填**(约半分钟,只读转录,只往自己账本里写 ac / acPre / lastCtx 三个字段,用量数字一个都不碰),
  把以前的会话历史上真压过的点补上。跑完之前这些老会话只有估算值

### 左栏 · 项目
- 项目列表带**固定序号**,按住卡片**拖动排序**,顺序永久记住
- 名称前的**彩色圆点**=业务线(视频/分发/工具/业务…)
- **红点+数字**=该项目有几个会话完成了还没看;点进会话红点才消
- 绿色**▣N 角标**=该项目有 N 个终端正在跑,点角标直达它的终端面板

### 中栏 · 项目与会话
- 顶部信息卡:项目定位、技术栈、亮点与坑(点开折叠);三个按钮:
  - **+ 新会话**:开一个全新 Claude 会话(内嵌终端)
  - **控制台(N)**:直达本项目终端面板;一个终端没有时自动开新会话
  - **打开目录**:资源管理器打开项目文件夹
- 会话卡:标题=会话摘要或你的首条指令;**悬停出现 ✎ 可改名**(Enter 存/Esc 取消);「打开」=内嵌终端接上原会话;「↗」=用外部 Windows Terminal 打开

### 右栏 · 记忆 / 资料 / 技能(三张分组卡)
- 🗄 **记忆 · 跨会话经验库**:Claude 每开新会话都是"失忆"状态,记忆就是它的长期大脑。`MEMORY.md` 是索引(每次会话自动装载),下面的记忆文件是具体经验(按需取用)。比如"某个坑踩过一次"记进去后,以后任何会话都不会再踩。CLI 里可用 `/memory` 浏览编辑
  - **两条官方硬限制**(2026-11-10 实测):`MEMORY.md` 有独立的大小上限(远小于单个记忆文件的 100KB),所以它只该放**一行一条短指针**,细节写进记忆文件;自动召回**只扫最近 200 个**记忆文件(按修改时间排),超出的不会被自动想起来
  - 但**掉出 200 不等于丢了** —— 索引里的链接每次都在,看得到、能主动让它去读。所以索引里的链接是兜底,**别为了瘦身把链接删掉**
- 📖 **资料 · 规矩与文档**:`CLAUDE.md`(项目规矩,Claude 每次会话必读必守)、README、修改记录、项目配置(.claude/settings)
- ⬡ **技能 · 流程手册**:`.claude/skills/` 下的自建斜杠命令,把固定流程(审查清单/发布流程)写成手册,CLI 里 `/技能名` 一键调用
- 顶部**搜索框**跨三组过滤,命中的组自动展开
- 三者分工一句话:**规矩(CLAUDE.md)每次全读、经验(记忆)索引常驻正文按需、流程(技能)点名调用**

## 三、内嵌终端(真 CLI)

- 跑的就是**真的 claude CLI**:TUI、权限弹窗、斜杠命令、计划模式原样全有
- **每个项目独立终端面板**:标签只显示当前项目的会话;标签文字=会话标题,**双击标签改名**

## 四、更新 · 小九 API · 常见问题

### Claude 更新
- 客户端启动时(及每 6 小时)自动检查 Claude Code 新版本,有更新时顶栏出现**金色提示**,点击即在终端里执行 `claude update`
- 也可手动:终端跑 `claude update`;版本通道在 `~/.claude/settings.json` 的 `autoUpdatesChannel`(latest/stable)

### 小九 / 外部代理控制
- 顶栏显示`小九 API 就绪 / 排队 / 执行中 / 异常`
- API 固定监听`127.0.0.1:8765`,不开放到局域网或公网
- 令牌自动保存在`%APPDATA%\claude-hub\agent-api.json`,界面不展示完整令牌
- 推荐使用`fork`模式:继承指定会话历史,但不占用 GUI 原会话、不覆盖输入草稿
- 支持本机图片和文件路径、任务队列、结果查询与任务持久化
- 详细接口和调用示例见`docs/agent-api.md`

### 常见问题
- **通知没声音/没弹?** 检查 `~/.claude/settings.json` 里的 Stop 钩子是否在;`~\.claude\hooks\notify.log` 有每次触发的诊断记录
- **会话列表里少了刚开的会话?** 新会话要等第一个回合完成后才会出现(转录落盘)
- **贴图后说读不到文件?** 看输入框里的路径是否带引号完整,pastes 目录在客户端安装目录下
- **用量数字突然变小 / 从头开始了?** 用量账本在 `%APPDATA%\claude-hub\usage-cache.json`,旁边有这些副本:
  - `usage-cache.json.bak` —— **最全的那一份**。只有账本「一条会话都不缺」时才会刷新,
    所以它可能好几个月不动,这是故意的:它的职责是永远不被残缺的数据盖掉。
  - `usage-cache.json.bak2` —— **最新的那一份**。每十分钟刷一次,第一次备份就会有。
    它可能比 `.bak` 少一些老会话(账本损坏后重建就是这样)。
  - `usage-cache.json.bad-<时间戳>-<随机>` —— 账本读不出来时,**原件**被原样另存成这个,供抢救。

  平时不用管:账本读不出来时,客户端会自动把这两份备份里「转录已经不在盘上」的老会话补回来,
  所以数字一般不会凭空变小。真要手工恢复的话:

  1. 先把客户端退干净;
  2. 要历史最全的就**复制** `.bak`、要最新的就复制 `.bak2`,改名成 `usage-cache.json`;
     ⚠️ **是复制,不是改名** —— 把 `.bak` 本身挪走,等于把「最全那份」的基准一起弄丢了;
  3. 再启动客户端。

  **别按文件大小挑哪份更全**:账本并不是只增不减 —— 老会话的转录被清掉之后,
  重建出来的账本会小一截,但它装的是最新的数字。大小说明不了哪份更全。

### 5.0 最该先会的十个

一句话版,细节看后面分类:

- `/context` — 看上下文用了多少、谁占的
- `/autocompact` — 设"多满才自动压缩",**省钱第一开关**
- `/clear` — 清空开新会话(旧的留在磁盘能回去)
- `/resume` — 回到任意旧会话
- `/compact` — 压缩当前对话,保留一份摘要
- `/model` — 换模型
- `/usage` — 看额度和花销
- `/insights` — 生成你的会话使用分析报告
- `/btw` — 问个岔开的小问题,不污染主线
- `/help` — 列出全部命令(永远最准)

### 5.1 上下文与省钱

这一组直接决定你的额度烧得快不快。**先搞懂这几个,比学会其它所有命令加起来都值钱。**

`/context [all]` — 看上下文现在用了多少、分别是谁占的,彩色格子图
```
/context         当前会话的占用分布
/context all     连系统提示、工具定义、已装技能一起算进去
```
用途:觉得"最近怎么这么贵"的时候,第一个该敲的就是它。

`/autocompact [auto|<tokens>]` — 设置"上下文多满才自动压缩"
```
/autocompact              打开选择界面
/autocompact 300k         堆到 30 万就自动压
/autocompact 200000       同上,写全数字也行
/autocompact auto         恢复默认(默认约等于模型上限才压)
```
取值范围 100k~1M。实际阈值 = min(这个值, 模型窗口上限) 再减 13000。
上下文每多一分,之后每次调用都要为它重复付费,所以调小它确实能压住**平时每次调用驮的量**。

**但本机现在故意设成 1M(= 几乎不自动压),原因:**
调小它省的是"平时驮的量",**省不了压缩本身**——压一次要把当时整个上下文完整读一遍,
而且压完是有损的(前面的对话被改写成摘要,压第二次就是摘要的摘要)。
真正省钱又不丢细节的做法是**在任务边界主动开新会话**,让自动压缩只当兜底。
顶栏「上下文」的**橙色收尾提醒线**(⚙️ 里设,默认 20 万)就是干这个用的。
**重要结论请随手写进 CLAUDE.md 或修改记录,别指望摘要替你记。**
也可以在启动时定:`claude --autocompact 300k`

`/compact [自定义摘要要求]` — 立刻压缩当前对话
```
/compact
/compact 重点保留排查过程和已经验证过的结论,代码细节可以略
```
把整段对话重写成一份摘要(通常 1~2 万 token)。**注意它自己是要花钱的**——要把整个上下文读一遍才能写出摘要,上下文有多大就读多少。所以"堆到很满再压"是最贵的用法。

`/clear [名字]` — 清空上下文,开一个全新会话。别名 `/reset`、`/new`
```
/clear
/clear 节点指挥舱-换机功能
```
**和 `/compact` 的本质区别:`/clear` 一个字都不留。** 新会话只会自动读到这些:全局 `CLAUDE.md`、项目 `CLAUDE.md`、`MEMORY.md` 那套记忆、SessionStart 钩子注入的内容、当前工作目录。
**之前聊过什么、查出过什么,它一概不知道。**
好处:不花压缩那笔钱,从干净的桌子起步。
用法建议:**清之前先让 Claude 把结论写进项目文件**,否则就真丢了。
旧会话照样留在磁盘上,`/resume` 随时回去。

`/skill-doctor` — 列出已加载但一直没用上的技能,它们在白占上下文
装了一堆插件之后值得跑一次。

### 5.2 会话管理

`/resume` — 打开会话选择器,挑一个接着聊
```
/resume
claude --resume <会话ID>     命令行直接定点恢复
claude --continue            接上最近一个
```
客户端会话卡上的「打开」按钮,底层就是它。

`/rename` — 给当前会话改名
```
/rename 独立站复刻Skill
```
注意:这改的是 **Claude Code 自己那套会话名**,别的会话 @ 它时用的就是这个名字。客户端会话卡上的改名是另一套(总控自己的标题),总控在你改名时会把两边同步。

`/recap` — 立刻生成一行会话摘要

`/branch [名字]` — 从当前这一刻**分叉**出一条新对话
```
/branch 试试换个架构
```
想试个没把握的方向时用:分叉去试,不满意直接丢掉,主线保持干净。

`/rewind` — 把代码和/或对话回退到之前某个检查点(双击 Esc 也能调出)
代码和对话可以**分开**选择退不退,比如"代码退回去但保留我们讨论过的结论"。

`/fork <指令>` — 开一个后台 agent,**继承完整对话**替你干活
```
/fork 把刚才讨论的三个方案各写一份设计稿
```

`/subtask <任务>` — 派一个子代理,带着你的完整上下文去干,结果回到这里
```
/subtask 独立复核刚才那个修复,重点找我漏掉的同类问题
```
和 `/fork` 的区别:`/subtask` 结果回到当前对话,`/fork` 是甩到后台独立跑。

`/btw [问题]` — 问个岔开的小问题,**不打断也不污染主线**
```
/btw 顺便问下 git stash pop 冲突了怎么办
```
平时你随口问的"顺便问一句",它和回答会**永久留在上下文里**跟着跑一辈子。用这个就不会。

`/export [文件名]` — 导出整段对话到文件或剪贴板
`/copy` — 复制 Claude 最后一条回复(`/copy 3` 复制倒数第三条)
`/clipboard` — 把整段对话复制到系统剪贴板
`/stop` — 停掉后台会话(转录和工作树都保留)

### 5.14 省额度的几条实战经验

1. **先看 `/context`,再谈省钱。** 不知道上下文被谁占满,改什么都是瞎调。
2. **`/autocompact` 设 200k~300k。** 默认几乎等于不节流。这是单项收益最大的改动。
3. **工具返回是大头。** 实测一个长会话里,"发给工具的参数 + 工具返回"能占到七成以上,真正的对话内容不到两成。所以少让 Claude 做无谓的全文件读取、让它用 Grep 精确定位,比什么都省。
4. **轻活换 Sonnet。** `/model sonnet` 一句话的事。
5. **岔开的问题用 `/btw`。** 不然它会永久留在上下文里。
6. **长会话该退休就退休。** 跑了几个月的会话,结论写进 `CLAUDE.md` / 修改记录,然后 `/clear` 开新的。比一直 `/compact` 省:压缩本身要把整个上下文读一遍才能写摘要,上下文越大这笔钱越贵。
7. **别让 effort 一直挂在 xhigh。**

### 5.15 几个容易搞混的

**`/clear` vs `/compact`**
- `/clear` 一个字不留,新会话只读 CLAUDE.md 和记忆。不花压缩的钱。
- `/compact` 留一份摘要,它还记得个大概。但压缩本身要读一遍全部上下文,很贵。

**`/compact` vs 自动压缩**
- 一样的东西,区别只是谁触发。`/autocompact` 设的就是自动那次的阈值。

**`/fork` vs `/subtask`**
- `/fork` 甩后台独立跑,不回来。
- `/subtask` 结果回到当前对话。

**`/branch` vs `/clear`**
- `/branch` 保留之前的上下文,从这一刻分出一条新线。
- `/clear` 清空重来。

**技能 vs 命令**
- `/help` 里列出来的是内置命令。
- `/技能名` 是你自己或插件装的流程手册(在 `.claude/skills/`),本手册标了 **[插件]** 的都是。

## 六、用到了哪些开源项目

分两块:**总控客户端自己**是拿什么搭的,和**你这台机器的 Claude Code 里装了什么**。
第五章里标 **[插件]** 的那些命令,来源就在下面第二块。

本章的版本号和许可证都是从本机 `node_modules` 里逐个读出来核对的,不是凭印象写的。

### 6.1 总控客户端(claude-hub 本体)

本体按 **AGPL-3.0** 开源。用到这些:

Electron 43.2.0 · MIT
    桌面外壳。界面本身是一个网页,另一个「主进程」负责开终端、读文件、发系统通知。

@xterm/xterm 6.0.0 · MIT
    内嵌的那个真终端。终端里的路径能点开,用的就是它的 registerLinkProvider 接口。

@xterm/addon-fit 0.11.0 · MIT
    终端随窗口大小自动算列数。改字号之后重新排版也靠它。

@lydell/node-pty 1.2.0-beta.14 · MIT
    真正的伪终端进程。没有它只能「跑条命令看输出」,不能像真终端那样交互。

electron-updater 6.8.9 · MIT
    顶栏那个「有新版」提示和一键更新。

misans 4.1.0 · Apache-2.0
    界面中文字体,小米的 MiSans,可免费商用(npm 上这个是 dsrkafuu 做的子集化版本)。

qrcode 1.5.4 · MIT
    手机连总控时屏幕上那个二维码。

electron-builder 26.15.3 · MIT
    打包成 exe 用的。只在开发时跑,不进安装包。

**没有用任何前端框架。** 界面是一个 `index.html` 里的原生 JS,没有 React / Vue,
也没有打包构建步骤 —— 改完直接 `npm run sync` 重启就能看到。

### 6.2 你这台机器的 Claude Code 环境

这部分不属于总控,是 Claude Code 自己的扩展,但第五章里很多命令是它们带来的。

**GSD** — 23 个技能 + 22 个子代理
    `/gsd-new-project` `/gsd-plan-phase` `/gsd-execute-phase` `/code-review` 这些都是它的。
    注意:**它不是以「插件」方式装的**,而是直接铺在
    `~/.claude/skills/gsd-*` 和 `~/.claude/agents/gsd-*` 里的文件。
    所以 `/plugin` 列表里看不到它,换台机器要自己把这些文件带过去。

**Superpowers 6.3.0** — 官方插件市场(claude-plugins-official)
    工程纪律那一套:系统化调试、测试先行、完成前验证、写计划、并行派子代理。
    这个是真插件,`enabledPlugins` 里有登记。

**frontend-design** — 同一个官方市场
    做界面时的设计指引。

**你自己写的 6 个命令** — `~/.claude/commands/`
    `/decide` 二选一决策 · `/experiment` 最小实验 · `/explain` 双层解释 ·
    `/factcheck` 事实核查 · `/reflect` 灵魂拷问 · `/teardown` 反向拆解。

**MCP 服务** — 全局只挂了 heygen 一个
    其余都是会话级按需加载的(浏览器控制、文档、日历那些)。

### 6.3 顺带说一句:这些东西是要占上下文的

`/context` 实测(2026-11-09,Opus 5.5):

    系统提示         4.3k
    系统工具        22.5k
    MCP 服务说明     1.5k
    子代理(22 个)    1.7k
    记忆文件(3 个)  17.3k
    技能(90 个)      9.0k
    -------------------------
    合计            约 5.6 万

**这 5.6 万是地板价** —— 一句话还没说就已经占上了,而且**每一次调用都要重新付一遍**。
装得越多,地板越高。

所以:
- 装了用不上的技能/插件,记得拿掉。`/skill-doctor` 会列出一直没用上的那些。
- MCP 工具现在是「按需加载」,不占地板(实测 148 个工具 0 token),这点不用担心。
- **记忆文件 17.3k 是第二大头**,`MEMORY.md` 那份索引每次都会整份装载,别让它无限长。
