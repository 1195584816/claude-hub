00

一句话说清全部

你的理解是对的:skill、技能、/reflect,就是同一样东西。

所有花样,本质都是同一件事:一段你写好的话,在某个时机被塞给 Claude。

区别只在两点——什么时候塞,和谁来决定塞。就这么简单。理解了这两句,下面所有东西都是它的变体。

好比对应的机制什么时候塞
贴在墙上的公司规章CLAUDE.md每次都在,不用叫
抽屉里的操作手册技能 / 斜杠命令要用了才拿出来
叫个同事去干子代理派活时
门禁刷卡机钩子固定动作自动触发
排班表定时任务到点自动跑

你问的那个:skill 和 /reflect 是一回事吗?

是,一模一样。这一版里,下面这两个文件效果完全相同:

~/.claude/commands/reflect.md 单文件 ~/.claude/skills/reflect/SKILL.md 目录

都能打 /reflect 调用,都能被 Claude 自己判断着调用。唯一的差别是形态:

  • 命令是一个文件——就一段话,写完就完事。
  • 技能是一个文件夹——可以在旁边放 Python 脚本、放参考表格、放模板。

所以选哪个很好判断:只有一段话就用命令;要带附件才用技能。你的 /reflect 就一段话,用命令是对的。

怎么验证的 claude --help 里 --disable-slash-commands 这个开关,说明文字原文写的是 "Disable all skills"(关闭所有技能)—— 官方自己就把斜杠命令当技能。而且我建好 reflect.md 之后,正在跑的会话立刻把它列进了技能清单。

唯一需要你上心的事:哪些是「每次都花钱」的

Claude 每回答一次,都要把上下文里的东西重新读一遍——常驻的内容,你之后每一轮对话都在为它付费。

常驻 每次对话都塞进去。写 3000 字,你之后每一轮都花这 3000 字的钱。
按需 平时只占一行简介,被叫到才展开全文。

写错了 把「这个项目怎么部署」「后台有哪几个模块」写进 CLAUDE.md。

这些代码里本来就能看出来,你却让它每轮重复计费。
写对了 CLAUDE.md 里只写看代码看不出来的判断:

「这个接口线上有人在用,别改签名」
「测试跑不过先看 JDK 版本对不对」
01

每次都在的话 常驻

不用你叫,每次对话自动带上。所以必须短。
~/.claude/CLAUDE.md 你的总规矩,所有项目都带上 项目/CLAUDE.md 这个项目的规矩,每次都带 项目/CLAUDE.local.md 只在你这台机器上,不进 git 项目/子目录/CLAUDE.md 只有动这个目录里的文件才带上 项目/.claude/rules/*.md 拆开写;加 paths 就变按需

省钱技巧一 · 规矩放到子目录里

如果你的项目前端后端都在一起,把前端规矩写进 web/CLAUDE.md,后端规矩写进 server/CLAUDE.md。

效果:Claude 改前端时只带前端规矩,改后端时只带后端规矩,互不打扰。根目录那份 CLAUDE.md 才是永远都带的,留给真正通用的几条。

省钱技巧二 · 按文件类型触发的规矩 .claude/rules/*.md

写一个规则文件,开头加上 paths,它就只在 Claude 碰到这类文件时才出现:

--- 文件:.claude/rules/前端规矩.md ---
---
paths: ["src/**/*.tsx", "src/**/*.ts"]
---

组件一律用函数式写法,禁止 class 组件。
样式只用 tailwind,不要写 css 文件。

Claude 改 Python 文件时,这段话根本不会出现,一分钱不花。项目大了之后这是最有效的一招。

把长东西挪出去 · @ 引用

在任何 CLAUDE.md 里写一行 @某个文件.md,就能把那个文件的内容接进来,而不用把正文抄进主文件。

你现在的全局 CLAUDE.md 第一行 @F:\claude-project\我的档案.md 就是这个用法。

02

叫了才来的话 按需

技能和斜杠命令。玩法最多的一层,全在文件开头那几行设置里。

放哪决定谁能用:

~/.claude/commands/名字.md 全局 · 任何项目都能 /名字 项目/.claude/commands/名字.md 只给这个项目 ~/.claude/skills/名字/SKILL.md 全局 · 能带附件 项目/.claude/skills/名字/SKILL.md 只给这个项目 · 能带附件
在总控面板里直接建 右栏现在有「斜杠命令」一块,点「+ 新建斜杠命令…」,填名字和说明、选全局还是本项目,建完直接进编辑器。 存盘立刻生效,不用重启任何东西。下面「技能」那块也会列出你已有的全局技能。

文件长什么样

就两部分:开头 --- 夹起来的设置,和下面的正文。正文写什么,Claude 就读到什么。

---
description: 检查这次改动有没有碰到计费逻辑
---

把刚才的改动过一遍,只看跟钱有关的地方:
扣费、充值、余额、提成、分红、货币换算。
有一处对不上就停下来告诉我,别自己改。

建好之后打 /检查计费,上面这段话就被送进去了。就这么简单——它真的只是一段话。

开头那几行能设什么

每一行都是一个玩法。下面挑真正有用的讲,配例子。

description — 最重要的一行

这句话有两个作用:你在斜杠菜单里看到的说明,以及 Claude 判断「要不要自己调用它」的唯一依据。

写得含糊 description: 检查代码

Claude 不知道什么时候该用,永远不会主动调它。
写得具体 description: 改动涉及扣费/充值/余额/提成时,用它核对金额逻辑

Claude 一改到计费代码就会主动想起它。

context: fork — 脏活别脏了你的对话

问题场景:你让 Claude「把 lib/ 下所有文件读一遍,找重复代码」。它读进来的几十个文件会一直占着你的对话,后面聊几句就满了。

解法:加一行 context: fork,它会另开一个分身去读,读完只把结论带回来,过程全部丢掉。

---
description: 全量扫一遍重复代码,只回结论
context: fork
background: false     # false=当场等结果,true=跑完再通知你
---
把 lib/ 下所有文件读一遍,列出重复实现的函数……

paths — 让它自己在对的时候冒出来

不用你记得调。给一个「数据库迁移检查清单」技能加上:

paths: ["**/migrations/**"]

以后只要 Claude 动到迁移文件,这个清单自动进场。你什么都不用做。

model — 便宜活别用贵模型

纯格式化、纯查资料这种活,加一行 model: haiku,省钱。复杂审查加 model: opus。

还有个 effort 控制思考深度:low / medium / high / max。

allowed-tools — 只让它干该干的

一个「只看不改」的审查命令,可以写 allowed-tools: Read, Grep, Glob,它就没法改你的文件了。也能细到 Bash(git *) 这种——只准跑 git 命令。

剩下的设置项,查表用

写什么什么意思
argument-hint斜杠命令后面显示的提示,比如 <PR编号>。
disallowed-tools反过来,禁用某些工具。下一条消息发出时自动解除。
agent配合 context: fork,指定派哪种分身去干。
isolation: worktree在一个临时的 git 副本里干活,不碰你的工作区。
disable-model-invocation设 true,Claude 就不准自己调,只有你打斜杠才触发。
user-invocable: false反过来,从菜单里藏起来,只让 Claude 自己用。
hooks这个命令生效期间临时挂钩子(见第 04 层)。
skills顺带把哪些别的技能也加载进来。
一个实测出来的坑 claude -p "/名字" 这种命令行直跑的方式不会展开斜杠命令(会被当成一个路径)。 只有交互式终端里打斜杠才展开。你平时用的就是交互式终端,不受影响。
03

找人替你干 按需

子代理。它的价值不是「更聪明」,是「花的不是你的上下文」。

很多人以为子代理是「换个人格」,其实不是。它真正的用处是:让别人去读那一堆文件,你这边只收结论。

你的对话空间是有限的。子代理是唯一能「花别人的额度干活」的机制。

~/.claude/agents/名字.md 全局 项目/.claude/agents/名字.md 只给这个项目

例子:一个只读的审查员

---
description: 代码审查员,只看不改,专挑逻辑漏洞
tools: Read, Grep, Glob      # 换掉默认工具,它连改文件的能力都没有
model: opus                  # 审查这种活值得用好模型
---
你是一个严格的代码审查员。只报你能给出复现步骤的问题,
拿不准的说拿不准,不要为了凑数编问题。

注意 tools 是「替换」不是「追加」——写了这三个,它就只有这三个,想改文件也改不了。这是最硬的护栏。

命令行干什么
--agent 名字让主会话自己变成这个角色。
--bg整个会话丢到后台跑,立刻返回。
claude agents管理后台跑着的代理。
/agents会话里的管理界面。
04

不靠自觉的规矩 按需

钩子。这是全篇唯一「跟模型愿不愿意无关」的机制。

先记住这条分界:

提示词 = 劝阻 在 CLAUDE.md 里写「每次改完代码都要跑 lint」。

Claude 可能会忘。事情一多就忘。
钩子 = 拦截 挂一个钩子在「改完文件」这个事件上。

这是外部程序在跑,模型忘不掉也绕不过。

所以判断很简单:凡是「每次都必须」的事,写提示词就是错的,该写钩子。

能挂在哪些时刻

时刻能拿它干什么
PostToolUseClaude 改完文件之后 —— 自动跑格式化、自动跑 lint。
PreToolUseClaude 动手之前 —— 可以拦下来。做硬护栏就靠它。
Stop一轮干完了 —— 你的完成通知就挂在这。
UserPromptSubmit你按回车的瞬间 —— 可以偷偷补充点上下文进去。
SessionStart / SessionEnd开场 / 收尾 —— 开场注入环境信息,收尾归档。
PreCompact / PostCompact上下文被压缩前后 —— 压缩前把关键结论存盘,很实用。
SubagentStart / SubagentStop分身起止。
Notification · TeammateIdle发通知时 · 协作空闲时。

例子:改完前端文件自动格式化

写进 .claude/settings.json:

{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",          // 改文件的动作才触发
      "hooks": [{
        "type": "command",
        "command": "npx prettier --write $CLAUDE_FILE_PATHS",
        "timeout": 30,
        "async": true                // 后台跑,不卡着你
      }]
    }]
  }
}

拦截怎么写

钩子脚本靠退出码说话:

  • 0 —— 放行,啥也不做。
  • 2 —— 拦下来。你打印到 stderr 的话会作为错误递给 Claude,让它改。
  • 其它数字 —— 出错了但不拦。

还有个进阶的 asyncRewake:后台跑,跑完退出码是 2 就把 Claude 叫醒。适合长任务。

你已经付过学费的坑 Stop 钩子必须同步读 stdin——用异步读会拿不到数据。这条在你的 claude-hub 项目里踩过。

06

装新本事

给它装新器官,而不是新说明书。有些事光靠写字是教不会的。
放哪装的是什么
.mcp.json外部系统的工具。你没法用文字教会它「怎么查我们的数据库」,得给它真工具。
.lsp.json语言服务器。让它拿到真正的类型信息和跳转定义,而不是读文本靠猜。强类型项目值得配。
.claude/output-styles/换掉默认的回答风格。/output-style 切换。
statusLine(设置里)底部状态栏跑你自己的脚本。
~/.claude/keybindings.json自定义快捷键。/keybindings 配置。
插件 /plugin把上面所有东西打成一个包——命令、技能、代理、钩子、主题、MCP 全打进去。
插件什么时候用得上 如果你哪天要把一整套配置发给别人,或者在几台机器之间同步——别手动拷目录,一定会漏。打成插件。
07

开工时的开关

不改任何文件,启动那一下决定这个会话怎么跑。

权限模式 —— 最该记住的一个

模式什么行为
plan只读,先出方案不动手。做架构设计、有取舍的改动,应该默认用这个 —— 正好对上你「先设计后实施」的习惯。
acceptEdits改文件不用问,其它照问。
manual每一步都问。
auto · dontAsk自动判定 · 不问但不等于全放开。
bypassPermissions全放开。只在断网沙箱里用。

面板里「新会话(计划模式)」按的就是 --permission-mode plan。

其它常用的

开关干什么
--model / --effort换模型 / 调思考深度。
-w, --worktree开一个 git 副本干活,不碰你正在改的东西。
--add-dir额外授权一个目录 —— 要跨项目引用文件时用。
-n 名字给会话起名,/resume 列表里好找。
--fork-session接着旧会话聊,但存成新的,不覆盖原来那条。
--max-budget-usd这次最多花多少钱。跑批量任务必设。
--json-schema强制返回符合指定格式的 JSON。做自动化管线时关键。

上下文快满了怎么办

  • /context —— 看现在上下文里到底装了什么。调优先看这个。
  • /compact —— 手动压缩。
  • /rewind —— 回滚到之前某个点。
  • /usage —— 看额度还剩多少。

设置文件谁说了算

从高到低:企业托管 → .claude/settings.local.json(你本机私有) → .claude/settings.json(项目,进 git) → ~/.claude/settings.json(你的全局)。

全部命令 速查

前面八层讲的是「怎么改 Claude 的行为」。这一层是「平时敲什么」——每条都带例子。
这份清单哪来的 不是凭记忆写的,是从本机 claude.exe(v2.1.319)的命令注册表里抠出来逐条核对的。 随版本会变,/help 永远最准。标 [插件] 的来自已装插件(GSD / Superpowers / 技能), 不是 Claude Code 自带——换台机器照着敲可能没有。

其余的用到再翻。

命令干什么
/context看上下文用了多少、谁占的
/autocompact设「多满才自动压缩」——省钱第一开关
/clear清空开新会话(旧的留在磁盘,能回去)
/resume回到任意旧会话
/compact压缩当前对话,留一份摘要
/model换模型
/usage看额度和花销
/insights生成你的使用分析报告
/btw问个岔开的小问题,不污染主线
/help列出全部命令(永远最准)

上下文与省钱

这一组直接决定额度烧得快不快。先搞懂这几个,比学会其它所有命令加起来都值钱。

/context [all] 看上下文被谁占满了

/context         当前会话的占用分布(彩色格子图)
/context all     连系统提示、工具定义、已装技能一起算

觉得「最近怎么这么贵」的时候,第一个该敲的就是它。不知道谁占满了,调什么都是瞎调。

/autocompact [auto|<tokens>] 设自动压缩的阈值

/autocompact              打开选择界面
/autocompact 300k         堆到 30 万就自动压(推荐)
/autocompact 200000       写全数字也行
/autocompact auto         恢复默认

省钱幅度最大的一个开关。默认 auto 对 1M 窗口的模型几乎等于不节流——要堆到接近 100 万才动手, 而上下文每多一分,之后每一次工具调用都要为它重复付费。

取值 100k~1M,实际阈值 = min(这个值, 模型窗口上限)。启动时也能定:claude --autocompact 300k

代价:压得越勤,摘要越频繁,久远的细节丢得越多。重要结论随手写进 CLAUDE.md 或修改记录,别指望摘要替你记。

/compact [摘要要求] 立刻压缩

/compact
/compact 重点保留排查过程和已验证的结论,代码细节可以略

把整段对话重写成一份摘要(通常 1~2 万 token)。注意它自己是要花钱的—— 要把整个上下文读一遍才写得出摘要,上下文有多大就读多少。所以「堆到很满再压」是最贵的用法。

/clear [名字] 清空开新会话 别名 /reset /new

/clear
/clear 节点指挥舱-换机功能

和 /compact 的本质区别:/clear 一个字都不留。新会话只会自动读到这些:

  • 全局 CLAUDE.md、项目 CLAUDE.md
  • MEMORY.md 那套自动记忆
  • SessionStart 钩子注入的内容
  • 当前工作目录

之前聊过什么、查出过什么,它一概不知道。好处是不花压缩那笔钱,从干净的桌子起步。

用之前 先让 Claude 把结论写进项目文件再清,否则就真丢了。旧会话本身还在磁盘上,/resume 随时回去。

/skill-doctor — 列出已加载但一直没用上的技能,它们在白占上下文。装了一堆插件之后值得跑一次。

会话管理

/resume 回到旧会话

/resume                       打开会话选择器
claude --resume <会话ID>      命令行定点恢复
claude --continue             接上最近一个

总控会话卡上的「打开」按钮,底层就是它。

命令干什么什么时候用
/rename给当前会话改名改的是 Claude Code 那套会话名;总控的标题会跟着同步

省额度的七条实战经验

  1. 先看 /context,再谈省钱。不知道上下文被谁占满,改什么都是瞎调。
  2. /autocompact 设 200k~300k。默认几乎等于不节流。单项收益最大的改动。
  3. 工具返回是大头。实测一个长会话里,「发给工具的参数 + 工具返回」占到七成以上,真正的对话内容不到两成。 所以少让它做无谓的全文件读取、让它用 Grep 精确定位,比什么都省。
  4. 轻活换 Sonnet。/model sonnet 一句话的事。
  5. 岔开的问题用 /btw。不然它永久留在上下文里。
  6. 长会话该退休就退休。跑了几个月的会话,把结论写进 CLAUDE.md / 修改记录,然后 /clear 开新的。 比一直 /compact 省:压缩本身要把整个上下文读一遍才写得出摘要,上下文越大这笔钱越贵。
  7. 别让 effort 一直挂在 xhigh。

就你现在的用法,四条建议

一 · 记忆索引行要压短

MEMORY.md 是每轮都带的。你现在五十多条,每条后面跟着一长串描述——这些字你之后每一轮对话都在花钱。

索引行只要够你和 Claude 判断「要不要点开」就行,细节留在正文文件里。

二 · 把「横向排查」做成 fork 命令

你经常让我「扫一遍别的端有没有同款问题」——这活要读一大堆文件,读完全堆在对话里。

做成一个带 context: fork 的命令,结论回来、过程丢掉,你的对话能撑久得多。现在面板里就能建。

三 · 计费红线应该是钩子,不是技能

薪果那边的计费护栏,现在靠的是「审查技能 + 你记得调」。这是劝阻,不是拦截。

改成 PreToolUse 钩子,匹配计费相关的文件路径,把条件写死——模型忘不掉也绕不过,这才叫护栏。

四 · 设计类任务默认走计划模式

你的习惯是「架构和有取舍的改动先出方案、确认了再做」。这件事有现成的开关:--permission-mode plan,面板里「新会话(计划模式)」就是。

比每次在提示词里叮嘱可靠——计划模式下它根本改不了文件。
